# DQA (Data Quality Analysis) 위키

## 핵심 지식

1. **라벨링 검수 자동화는 API 기반 워크플로우로 구현된다**
   Labelit API(`/api/v1` → `/api/v3` 버전 진화)를 통해 태스크 Export, Phase 상태 관리(`PreAnnotated`, `Submitted`), 관리자 계정 제출 등의 검수 파이프라인이 코드로 자동화됨. 2024년 중반부터 반복적으로 구현 및 디버깅됨.

2. **3D LiDAR annotation 품질 분석은 통계 검증보다 모델링 접근이 적합하다**
   고차원·고복잡도 데이터를 다수의 비고정 작업자가 생성하는 환경에서는 정석적 가설 검증보다, 데이터 표본 기반 모델링이 실효성이 높다는 결론 도출 (2025-09-19).

3. **Acceptance Criteria는 문서(Acceptance Minute) 형태로 공식화된다**
   납품 산출물이 요구사항을 충족하는지 발주자-수주자 간 합의를 기록하는 문서. DQA 결과를 대외적으로 증빙하는 수단으로 활용 가능 (2025-09-26).

4. **Scoring 로직은 Cross-Feature Validation으로 설계 검증이 필요하다**
   `Scoring v1.0 Cross-Feature Validation.ipynb` 기반으로 스코어링 로직의 논리적 설계 평가를 수행함. 피처 간 교차 검증이 품질 점수 산출의 핵심 구조 (2026-04-05).

5. **Multi-Agent 생태계로 DQA 파이프라인 자동화가 설계 중이다**
   Personal Knowledge Base 도메인 프로젝트(`nova_he...`) 기반으로 멀티 에이전트 에코시스템 설계 플랜이 승인되어 구현 진행 중 (2026-04-11~12). 신규 브랜치 전략으로 진행.

6. **실측 데이터 품질은 수집 차량의 하중(장비 무게)에도 영향을 받는다**
   장비 과적으로 인한 진동, 차체 기울기, 센서 캘리브레이션 오차 등이 LiDAR/카메라 데이터 품질에 직접 영향. 하드웨어 조건도 DQA 변수로 고려해야 함 (2025-07-21).
