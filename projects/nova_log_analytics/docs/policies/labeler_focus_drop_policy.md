# Labeler 작업 집중도 저하 탐지 정책 v0.9

**승인 상태**: Draft  
**작성자**: OpenAI Codex  
**적용 범위**: `projects/nova_log_analytics` 내 anomaly detection 기준 검토 및 Labeler role 작업 흐름 저하 신호 해석

---

## 1. 목적

본 문서는 Labeler 작업 로그를 기반으로 `작업 집중도 자체를 정밀 측정`하는 것이 아니라, `작업 집중도 저하 신호를 탐지`하기 위한 초기 운영 기준을 정의하는 것을 목적으로 한다.  
본 기준은 anomaly 관련 문서 및 runner에 반영된 관찰값을 근거로 수립한 `운영 기준 초안(v0.9)`이며, 향후 실측 분포 변화와 운영 해석 결과를 반영하여 버전업 방식으로 지속 보정한다.

---

## 2. 기본 원칙

- 본 기준은 `관찰 기반 운영 기준`으로 정의하며, 심리적 몰입 상태를 직접 측정하는 지표로 해석하지 않는다.
- 본 기준의 초점은 `집중도 수준 평가`가 아니라 `정상 작업 흐름에서의 이탈 신호 탐지`에 둔다.
- 초기 기준값은 Labeler의 실제 로그 패턴에 대한 관찰 결과를 바탕으로 설정한다.
- Reviewer, Manager 등 타 역할의 패턴은 참고 정보로 활용하되, Labeler 저하 탐지 기준의 직접 임계값은 Labeler 관찰값을 우선 적용한다.
- 기준 변경은 임의 조정이 아니라 누적 데이터 기반 재검토 결과를 바탕으로 `버전업` 방식으로 관리한다.

---

## 3. 기준 수립 배경

anomaly 문서 기준으로 현재 확인된 관찰값은 다음과 같다.

- Labeler의 일반적인 작업 패턴은 `짧은 이벤트 간격`을 보인다.
- 문서상 관찰값 기준, Labeler의 `p50 gap`은 대체로 `0~2초` 수준이다.
- Labeler의 `1분 초과 gap 비율`은 `1.5% 미만`으로 관찰되었다.
- 반면 Manager/Reviewer는 역할 특성상 이벤트 간격이 길어질 수 있어 동일 기준으로 해석하기 어렵다.

또한 현재 수집 로그는 객체 생성/수정/삭제, grouping, undo/redo 등 `명시적 command` 중심으로 구성되어 있으며, 마우스 휠, 클릭, 시점 이동, 탐색, 판단 시간 등은 충분히 수집되지 않는다.

따라서 본 기준은 `작업 집중도 자체를 직접 수치화하는 방식`보다 `Labeler의 정상 작업 패턴에서 이탈하는 gap 구조와 흐름 단절 신호를 탐지하는 방식`으로 정의한다.

---

## 4. 개념 정의

### 4.1 작업 집중도

본 문서에서의 작업 집중도는 작업 세션 내에서 작업자가 annotation 목적의 유효 작업 흐름을 지속적으로 유지하는 정도를 의미한다.

단, 현재 로그 구조만으로는 작업 집중도를 완전하게 측정하기 어렵기 때문에, v0.9에서는 이를 직접 평가 지표로 사용하지 않는다.

### 4.2 유효 작업 흐름

본 문서에서 유효 작업 흐름은 다음 두 요소를 포함한다.

- 객체 상태를 변화시키는 명시적 command 수행
- command 전후에 발생하는 합리적인 작업 준비, 검토, 판단 구간

### 4.3 작업 집중도 저하

작업 집중도 저하는 작업 세션 내에서 정상적인 Labeler 작업 패턴 대비 command 간 공백이 과도하게 길어지거나, 장기 공백이 반복적으로 발생하여 `유효 작업 흐름이 약화된 상태`를 의미한다.

### 4.4 작업 이탈

작업 이탈은 세션이 유지되고 있더라도 일정 시간 이상 유효 작업 흐름이 관측되지 않아 실질적인 작업 지속 상태로 보기 어려운 구간을 의미한다.

## 5. v0.9 저하 탐지 정의

### 5.1 판정 대상

- Labeler role 사용자
- 분석 단위는 `사용자 단위`
- 집계는 해당 사용자의 작업 로그 전체를 기준으로 수행

### 5.2 핵심 지표

#### `avg_gap`

- 이벤트 간 시간 차(`diff_sec`)의 평균
- 단위: 초(`seconds`)

#### `gaps_5min`

- `5분(300초)`을 초과하는 이벤트 간 gap의 개수
- 장시간 이탈 또는 작업 흐름 단절 빈도를 나타내는 보조 지표로 사용한다

### 5.3 v0.9 탐지 기준

다음 두 조건을 모두 만족할 경우 `집중도 저하 신호`가 관측된 것으로 판정한다.

```text
avg_gap > 30초
AND
gaps_5min > 10회
```

### 5.4 판정 레벨

- severity: `warning`
- 판정 의미:
  - 즉시 이상 행위, 저성과, 비정상 작업으로 확정하지 않는다.
  - 다만 정상적인 Labeler 작업 패턴 대비 `작업 흐름 저하 가능성`이 높은 상태로 판단한다.

## 6. 해석 원칙

본 기준은 `생산성 평가 점수`가 아니라 `저하 탐지 규칙`으로 해석한다.

따라서 결과 해석은 다음 원칙을 따른다.

- `탐지`:
  - 로그 패턴상 작업 흐름 저하 가능성이 있는 사용자를 식별한다.
- `평가`:
  - 실제 판단은 작업 맥락, 업무 유형, 세션 특성, 운영 이슈와 함께 종합 해석한다.
- 즉, warning은 `검토 필요 신호`이며 `저성과 확정 판정`을 의미하지 않는다.

---

## 7. v0.9 기준의 한계

본 기준은 다음과 같은 한계를 가진다.

- 현재 기준은 문서 관찰값을 기반으로 한 초기 버전이다.
- threshold는 Labeler 정상군의 대표 분포를 더 넓게 수집한 후 조정될 수 있다.
- `avg_gap` 단일 지표만으로 작업 집중도 전체를 설명하기는 어렵다.
- 현재 로그에는 마우스 휠, 클릭, 시점 이동, 탐색, 판단 시간 등 비명시적 작업 행위가 충분히 포함되지 않는다.
- 따라서 `무커맨드 시간`을 곧바로 `idle` 또는 `비집중 상태`로 단정해서는 안 된다.
- 향후에는 다음 항목을 반영한 보완이 가능하다.
  - `1분 초과 gap 비율`
  - 세션 길이별 gap 분포
  - task 난이도별 보정
  - feature별 기준 분리
  - 개인 절대값이 아닌 역할군 내 상대 위치(percentile) 기준

---

## 8. 정책 적용 방향

v0.9 단계에서 본 기준은 다음 방향으로 적용한다.

- `집중도 측정`보다는 `집중도 저하 탐지`를 우선 목표로 한다.
- `무행동 시간 전체`가 아니라 `설명하기 어려운 장기 공백 반복`을 주요 탐지 대상으로 본다.
- `단일 절대 점수`보다는 `저하 신호 여부`와 `검토 필요 대상 식별`에 초점을 둔다.
- 유효 작업시간 산정 정책과 직접 결합하기보다는, 우선 anomaly 탐지 및 운영 해석 기준으로 사용한다.

---

## 9. 버전업 원칙

다음 조건 중 하나 이상이 확인되면 기준 재검토 및 버전업을 수행한다.

- Labeler 로그 표본이 충분히 확대된 경우
- 툴 UX 또는 작업 방식이 크게 변경된 경우
- Policy/Workflow 변경으로 gap 분포가 이동한 경우
- 특정 feature에서 기존 기준의 오탐/미탐이 반복 확인된 경우
- 운영 해석상 현재 기준이 실제 집중도 저하를 잘 설명하지 못하는 경우
