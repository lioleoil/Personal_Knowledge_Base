## 서론: 하이브리드 클라우드 데이터 파이프라인의 전략적 가치
현대 기업의 데이터 전략은 온프레미스의 안정성과 클라우드의 유연성을 동시에 확보하는 하이브리드 아키텍처로 진화하고 있습니다. 특히 비정형 데이터(이미지, 로그, 비디오 등)가 기업 데이터의 80% 이상을 차지함에 따라, 분산된 소스에서 데이터를 통합하여 **AI-Ready** 상태로 전환하는 역량이 비즈니스 의사결정의 핵심 경쟁력이 되었습니다.
본 보고서는 온프레미스 스토리지인 **Qumulo**와 클라우드 데이터 레이크하우스 플랫폼인 **Databricks**를 연동하여, 데이터 사일로를 제거하고 확장 가능한 데이터 수집 기반을 구축하기 위한 아키텍처 전략을 제시합니다. 이 전략의 핵심은 단순한 데이터 이동을 넘어, 보안과 거버넌스가 보장된 상태에서 데이터의 원본성을 유지하며 클라우드로 유입시키는 데 있습니다. 그 첫 단계로 Qumulo의 데이터를 AWS S3로 안전하게 전송하기 위한 **Shift-To** 전략을 살펴봅니다.

## 1. Qumulo Shift-To 기반 S3 데이터 동기화 전략
온프레미스 및 클라우드 네이티브 Qumulo(CNQ)의 데이터를 클라우드로 전송할 때, 가장 효율적인 수단은 **Shift-To** 기능입니다. 이는 데이터 일관성을 유지하면서도 전송 효율을 극대화하는 엔터프라이즈급 동기화 메커니즘을 제공합니다.
### 1.1. Shift-To 메커니즘 및 전송 효율성
Shift-To는 전송 시작 시 **임시 스냅샷**을 생성하여 작업 중 발생하는 데이터 변경에 관계없이 특정 시점의 일관성을 보장합니다. 또한, 이미 복사된 파일 중 수정되지 않은 항목은 제외하는 **증분 복사** 방식을 통해 대규모 데이터 전송 시 대역폭과 시간을 절약합니다.
이때 정의된 **S3 Prefix(폴더)** 구조는 후속 단계인 Databricks Unity Catalog 설정의 물리적 기초가 되므로, 소스별(온프레미스, CNQ 등)로 고유한 경로를 설계하는 것이 아키텍처 설계의 핵심입니다.
### 1.2. 메타데이터 보존 및 기술적 제한 사항 평가
Shift-To는 파일 시스템의 메타데이터를 최대한 보존하려 노력하지만, S3의 객체 스토리지 특성상 일부 항목의 변형이나 누락이 발생합니다.
| 구분           | 포함 항목 (보존)                           | 제외 항목 (미보존) 및 대응 방안                                                                 |
| -------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| **메타데이터** | 사용자 정의 메타데이터 (S3 태그로 변환)    | **ACL, SMB 확장 속성:** S3 접근 정책(IAM/UC)으로 재설계 필요                                   |
| **시간 정보**  | (없음)                                     | **btime, mtime 등:** S3 `LastModified`로 대체. 원본 시간 필요 시 별도 사이드카 파일 생성 권장   |
| **엔터티/구조**| 파일 경로 (S3 Key로 유지)                  | **디렉토리 객체:** S3는 flat namespace이므로 디렉터리 객체는 생성하지 않고 경로 구조만 유지     |
| **기타**       | 데이터 기본 스트림                         | **심볼릭 링크, 장치 파일:** 복사 대상에서 제외                                                  |

**[핵심 주의사항 및 전략적 제언]**
- **메타데이터 제약:**  
  S3는 태그 10개, 메타데이터 2KB로 제한이 엄격합니다. Qumulo에서 이를 초과하는 메타데이터를 운용 중일 경우, 복사 과정에서 유실될 위험이 있으므로 사전 정제가 필수적입니다.
- **Content-Type 기본값:**  
  Shift-To를 통해 전송된 모든 파일은 기본적으로 `binary/octet-stream`으로 설정됩니다. 브라우저에서 직접 미리보기가 필요한 비정형 데이터의 경우, Databricks 수집 단계에서 메타데이터를 재정의하거나 AWS 콘솔에서의 사후 처리가 필요할 수 있습니다.
- **데이터 무결성:**  
  전송 과정에서의 손상을 방지하기 위해 Shift-To는 **SHA256 체크섬**을 생성하여 S3 객체 메타데이터에 저장합니다. 이는 데이터 전송의 신뢰성을 증명하는 중요한 근거가 됩니다.

## 2. Databricks Unity Catalog 기반 보안 및 인프라 구성
S3로 동기화된 데이터는 Databricks의 **Unity Catalog(UC)**를 통해 현대적인 거버넌스 체계 안으로 편입됩니다. 과거의 DBFS 마운트 방식이 가졌던 보안 취약점과 관리 복잡성을 해결하는 것이 이 단계의 목적입니다.
### 2.1. 인프라 자동화: CloudFormation Quickstart 활용
Databricks에서 권장하는 **AWS CloudFormation Quickstart 템플릿**을 사용하면 S3 버킷과 Databricks 간의 연결을 신속하게 자동화할 수 있습니다.
- **자동화된 자격 증명:**  
  필수 요소인 스토리지 자격 증명(Storage Credential)과 IAM 역할을 자동 생성하여 수동 설정 시의 실수를 원천 차단합니다.
- **외부 위치(External Location) 정의:**  
  Shift-To에서 지정한 S3 Prefix 경로를 UC의 **외부 위치**로 등록함으로써, 데이터 이동 없이도 중앙 집중식 권한 관리가 가능해집니다.
### 2.2. 레거시 전환 및 비교 분석
기존 환경에서 DBFS 마운트를 사용하던 조직은 Unity Catalog Volumes로의 전환이 필수적입니다. 마운트 정보를 변경한 후에는 반드시 `dbutils.fs.refreshMounts()`를 실행하여 클러스터 간 일관성을 확보해야 하나, 장기적으로는 모든 비정형 데이터를 UC Volumes로 관리하는 전략을 권고합니다.
| 비교 항목        | DBFS 마운트 (Legacy)                                  | Unity Catalog Volumes (Modern)                             |
| ---------------- | ------------------------------------------------------ | ---------------------------------------------------------- |
| **거버넌스/보안**| 워크스페이스 단위 관리 (권한 노출 위험)              | 중앙 집중식 권한 제어 (READ/WRITE VOLUME)                 |
| **인증 방식**   | Access Key 하드코딩 가능성 높음                       | IAM Role 기반 스토리지 자격 증명 활용                     |
| **사용자 경험** | `/mnt/` 경로 기반 로컬 파일 접근                      | Catalog Explorer를 통한 직관적 파일 탐색                  |

## 3. Auto Loader 기반 비정형 데이터 증분 수집 전략
보안 인프라가 구축된 후에는 대규모 비정형 데이터를 효율적으로 레이크하우스로 수집해야 합니다. 이때 발생하는 가장 큰 리스크는 수백만 개 이상의 파일 리스팅에 따른 **API 비용 및 성능 저하**입니다.
### 3.1. 최적의 엔진: Auto Loader (cloudFiles)
**Auto Loader**는 체크포인트를 활용하여 새로운 파일만 증분 수집하는 표준 방식입니다. 특히 파일 수가 방대한 경우, 일반적인 디렉터리 리스팅 방식은 S3 API 호출 비용을 기하급수적으로 증가시키므로 반드시 **알림 모드(Notification Mode)**를 사용해야 합니다. SQS/SNS를 통한 이벤트 구독 방식을 통해 리스팅 부하를 제거하고 확장성을 확보할 수 있습니다.
### 3.2. 메달리온 아키텍처 및 구현
수집된 비정형 데이터는 **브론즈(Bronze)** 레이어에서 원본 형식을 유지하며 관리됩니다. 이는 데이터 유실 시 재처리가 가능하게 하며, 데이터의 가명화나 전처리를 위한 기초 단계가 됩니다.
**[Auto Loader 증분 수집 구현 (PySpark)]**
```python
# S3 외부 위치에서 비정형 데이터를 안전하게 수집하는 로직
df = (
    spark.readStream
    .format("cloudFiles")
    .option("cloudFiles.format", "binaryFile")      # 비정형 파일 처리를 위한 포맷
    .option("cloudFiles.useNotifications", "true")  # SQS/SNS 알림 모드로 API 비용 절감
    .load("s3://managed-external-location/qumulo_data/")
)
(
    df.writeStream
    .trigger(availableNow=True)  # 신규 데이터만 처리 후 종료 (배치 형태)
    .option("checkpointLocation",
            "s3://managed-external-location/checkpoints/bronze_data")
    .table("main.bronze.unstructured_assets")

데이터 사이언스 워크플로우에서 원시 파일에 즉각적인 탐색적 접근이 필요할 경우, Auto Loader 외에도 **Unity Catalog Volumes**를 병행하여 UI 기반의 로컬 폴더 경험을 제공하는 것이 유리합니다.

## 결론: 하이브리드 데이터 통합 설계를 통한 운영 효율 최적화 및 AI 확장 기반 확보
S3 Sync 기반의 하이브리드 데이터 통합 설계 구조는 비정형 데이터를 비용 효율적으로 처리·보존하면서도 원본 맥락을 유지해, 단순 저장 자산을 즉시 활용 가능한 AI 자산으로 전환하는 기반을 만듭니다. 이는 데이터 운영 비용을 줄이는 동시에, 향후 AI 기반 서비스 확장까지 고려한 전략적 데이터 인프라로 기능하게 됩니다.
1. **데이터 처리 효율성 및 비용 최적화**  
   Unity Catalog Volumes를 통해 **zero-copy** 방식으로 디렉터리를 로컬 폴더처럼 즉시 브라우징하고 탐색할 수 있으며, **지능형 증분 수집**을 통해 불필요한 S3 리스팅 비용을 절감하고 데이터 파이프라인의 확장성과 처리 속도를 극대화합니다.
2. **데이터 보존 및 무결성**  
   Qumulo의 **Shift-To** 기능을 활용한 S3 Sync는 온프레미스의 방대한 비정형 데이터를 클라우드 네이티브 환경으로 **안전하고 일관되게 이전**하며, 삭제 비동기화 특성(원본 삭제 시 S3 유지, 임시 스냅샷 방식)으로 **데이터 백업 및 보존 효과**를 제공합니다.
3. **AI-Ready 기반 구축**
