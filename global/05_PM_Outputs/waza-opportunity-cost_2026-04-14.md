# Waza 기회비용 평가 — Windows 환경 대안 분석

> **작성**: 2026-04-14 | **맥락**: 현재 환경 Windows 11, Waza는 macOS 전용

---

## 핵심 결론

**Waza는 현재 환경(Windows 11)에서 실행 불가능하다.**  
Swift/Xcode 기반이므로 포팅 없이는 사용 자체가 막혀 있다.  
따라서 Waza에 투자하는 학습·설정 시간은 **현재 환경 기준 완전 매몰비용**이다.

---

## 1. Waza 도입의 기회비용 구조

| 비용 항목 | 내용 |
|----------|------|
| 학습 비용 | Swift/Xcode 환경 구축, WKWebView 커스터마이징 이해 |
| 전환 비용 | 각 앱별 Config 작성, 테스트, 단축키 재설정 |
| 유지 비용 | 오픈소스 유지보수 불확실성, 업데이트 직접 관리 |
| **기회 비용** | **같은 시간에 Windows 네이티브 솔루션으로 즉시 동일 효과 달성 가능** |

## 3. 각 대안 상세 평가

### 3.1 Edge PWA (권장 1순위)
- **방법**: `edge://apps` → 사이트 접속 → `...` → "이 사이트를 앱으로 설치"
- **장점**: 추가 설치 없음, 독립 창, 작업 표시줄 고정, 오프라인 지원(일부), OS 알림 통합
- **단점**: 커스터마이징 한계 (아이콘·UserAgent 직접 수정 불가)
- **적합 앱**: Notion, Gmail, Jira, Claude, GitHub

### 3.2 nativefier (중급 사용자)
```bash
npm install -g nativefier
nativefier --name "Notion" "https://notion.so"
```
- **장점**: CLI로 빠른 생성, 아이콘·UserAgent·크기 지정 가능
- **단점**: Electron 기반 → 메모리 부담 (앱당 150~300MB)
- **적합 케이스**: 세밀한 설정이 필요한 사내 대시보드, 인증 필요 서비스

### 3.3 Tauri wrapper (장기 투자)
- **장점**: Waza와 동일한 경량 철학, Rust 기반 → 메모리 30~50MB
- **단점**: Rust + Tauri 학습 필요, 앱당 직접 빌드 필요
- **권장 시점**: nativefier의 메모리 부담이 실제로 문제가 될 때

## 4. 기회비용 수치 비교

| 시나리오 | 초기 설정 시간 | 앱당 추가 시간 | 실행 가능 여부 |
|---------|-------------|-------------|------------|
| Waza (macOS) | 2~3시간 | 15~30분 | ❌ Windows 불가 |
| Edge PWA | **5분** | **2분** | ✅ |
| nativefier | 30분 (npm 설치) | 5분 | ✅ |
| Tauri | 4~8시간 | 30~60분 | ✅ |

---

## 5. 권장 전략

### 즉시 실행 (오늘)
Edge PWA로 다음 5개 앱부터 설치:
1. Notion
2. Gmail
3. Jira (사내 대시보드)
4. Claude
5. GitHub

**예상 소요 시간**: 10분 이내, 효과는 Waza와 동일

### 단기 (1~2주)
커스터마이징이 필요한 앱은 nativefier로 보완.  
특히 UserAgent 조정이 필요한 사내 시스템에 적합.

### 장기 (필요 시)
Tauri 기반 래퍼 직접 빌드.  
현재 Python/.scripts 자동화 역량 고려 시 진입 장벽 낮음.

---

## 6. 최종 판단

> Waza 전략 리포트의 도입 목표(브라우저 탭 감소, 리소스 최적화, 업무 집중도 향상)는  
> **Edge PWA만으로 80% 이상 달성 가능**하며, 추가 비용은 사실상 0이다.  
> Waza 자체보다 **Waza가 해결하려는 문제**에 집중하는 것이 합리적이다.
