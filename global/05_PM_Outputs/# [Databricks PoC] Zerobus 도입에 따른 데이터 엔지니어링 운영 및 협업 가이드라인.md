# 서론: Zerobus 도입과 데이터 파이프라인의 패러다임 전환
Zerobus의 도입은 단순한 도구의 교체를 넘어, 데이터 수집 패러다임을 '인프라 관리'에서 **'API 중심의 전략적 큐레이션(ELT)'**으로 전환하는 핵심적인 전략적 선택입니다. Zerobus는 `App → Zerobus SDK → Delta Table`이라는 서버리스 기반의 직통 구조로 단순화합니다. 이러한 혁신은 데이터 팀이 인프라 운영의 늪에서 벗어나 비즈니스 가치 창출에 집중하게 함으로써 **'Time-to-Insight(통찰력 확보 시간)'**을 획기적으로 단축합니다.
이 변화를 식당 운영에 비유하자면, 과거에는 식재료가 들어오는 트럭 문 앞에서 모든 전수 검사를 수행하느라 정작 요리할 시간이 부족했던 **'사전 검증(ETL)'** 방식이었습니다. 반면, Zerobus 체계는 신선한 재료를 주방 창고(Bronze)에 즉시 입고시킨 뒤, 실제 요리 직전(Silver)에 셰프의 전문적인 기준에 맞춰 꼼꼼하게 다듬고 검증하는 **'사후 거버넌스(ELT)'** 방식으로의 진화를 의미합니다. 이러한 아키텍처의 단순화는 필연적으로 데이터 레이어별 역할의 근본적인 변화와 실무자 간의 고도화된 R&R 재정립을 요구합니다.
---
## 1. 메달리온 아키텍처 레이어의 재정의 및 전략적 가치
Zerobus 환경에서는 수집 단계에서의 복잡한 가공이 배제됨에 따라, 데이터의 신뢰성을 확보하는 전략적 요충지가 하류(Downstream)로 이동합니다. 각 레이어의 역할은 다음과 같이 엄격하게 재정의되어야 합니다.
### 1.1. 메달리온 레이어별 전략적 가치 비교
| 레이어명  | 핵심 역할              | 주요 특징                                                                 | 가치 비중 변화        |
| --------- | ---------------------- | ------------------------------------------------------------------------ | ---------------------- |
| **Bronze** | Raw Landing Zone       | 가공과 검증을 배제한 순수 원본(Raw Event) 저장소 및 완충 지대           | **감소** (단순 저장)   |
| **Silver** | **제1차 품질 방어선** | 핵심 QA 및 시맨틱 레이어, 데이터 신뢰성 확보의 최전선                   | **급증** (전략적 핵심) |
| **Gold**   | Business Expression    | KPI 산출 및 시각화, 고도의 의사결정 로직 투영 계층                      | **유지** (최종 가치)   |

### 1.2. Silver 레이어의 전략적 격상 배경
Zerobus는 SDK 수준에서 데이터 형식(Schema)의 최소한의 유효성만 판단하여 전송합니다. 즉, 데이터의 비즈니스적 의미나 시맨틱 무결성은 보장하지 않습니다. 따라서 **Silver 레이어는 수집 단계에서 생략된 모든 복잡한 검증 로직을 처리하는 중추적인 역할**을 수행해야 합니다. 이곳은 이제 단순한 정제 단계를 넘어, 전사적 데이터 신뢰성을 결정짓는 가장 전략적 가치가 높은 계층으로 기능합니다. 이러한 변화는 실무자의 구체적인 업무 범위(R&R) 변화로 직결됩니다.
---
## 2. 데이터 엔지니어(DE)와 애널리틱스 엔지니어(AE)의 R&R 재정립
기술 혁신은 실무자의 과업을 '단순 운영'에서 '고부가가치 설계'로 이동시켜야 합니다. Zerobus 환경에서 DE와 AE는 **'책임의 대칭성(Responsibility Symmetry)'** 모델을 바탕으로 상호 보완적인 전문성을 발휘합니다.
### 2.1. DE: 인프라 관리자에서 '데이터 규약 설계자'로
* **고부가가치 과업 전환:** Zerobus의 서버리스 구조를 통해 절감된 **30~40%의 인프라 운영 시간은 반드시 데이터 규약(Data Contract) 설계 및 아키텍처 거버넌스 강화에 할당**해야 합니다.
* **가용성(Availability) 마스터:** 스트림별 처리량(Throughput)을 모니터링하고 API 연결의 견고함을 관리하여, 데이터가 중단 없이 Bronze 레이어까지 도달하도록 보장합니다.
### 2.2. AE: 데이터 마트 구축자에서 '품질 보증 수호자'로
* **직접적인 품질 책임:** Silver 레이어에서 **SQL 기반의 ELT 검증 로직을 직접 구현**하며, 수집 후 거버넌스 체계를 실무적으로 완성합니다.
* **신뢰성(Reliability) 보장:** 데이터의 비즈니스적 의미(Semantic)를 정의하고 메트릭 정합성을 수호하여, 최종 사용자가 데이터를 의심 없이 의사결정에 활용할 수 있도록 합니다.
### 2.3. 책임의 대칭성 모델
* **DE (가용성):** 데이터가 제시간에, 누락 없이 흐르고 있는가? (**흐름의 가용성**)
* **AE (신뢰성):** 도착한 데이터가 비즈니스적으로 정확한 의미를 내포하는가? (**내용의 신뢰성**)

## 3. Silver 레이어의 데이터 품질 검증(QA) 및 신뢰성 확보 전략
Silver 레이어에서의 QA는 단순한 오류 탐지를 넘어, 데이터의 **가시성(Visibility)**과 **신뢰성(Reliability)**을 동시에 확보하는 고도의 전략적 프로세스입니다.
**[4대 품질 검증 프레임워크]**
1. **기술적 정합성(Technical Integrity):**
   * **필수값 및 타입 검증:** 데이터 규약에 정의된 Null 체크 및 Zerobus SDK 정의 타입 유지 여부 확인.
   * **스키마 일치성 확인:** 원천 시스템의 변경이 하류 파이프라인을 파괴하는 **스키마 일치성 오류(Schema Drift)**를 선제적으로 차단.
2. **비즈니스 로직 및 시맨틱(Business Logic & Semantic):**
   * **도메인 규칙 및 Mapping Table:** "결제 금액 > 0"과 같은 비즈니스 규칙을 적용합니다. 특히, CRM과 ERP 등 이기종 소스 간의 식별자를 통합하는 **Mapping Table 관리를 통해 '전사적 통합 모델'을 구축**합니다.
   * **정규화 및 중복 제거:** 원천 이벤트를 엔티티 단위로 정규화/세션화하고 데이터 유일성을 보장합니다.
3. **Unity Catalog 기반 모니터링:**
   * **자동화된 계보(Lineage) 및 영향 분석:** 소스부터 최종 뷰까지의 흐름을 추적합니다. AE는 이를 활용해 데이터 변경 시 **하류의 어떤 대시보드가 영향을 받을지 미리 파악하는 '영향 범위 분석(Impact Analysis)'**을 반드시 수행해야 합니다.
   * **품질 어설션(Assertion):** 이상 징후 포착 시 SQL 기반 검증 로직을 상시화하여 품질 수준을 지속적으로 고도화합니다.
4. **보안 및 권한:**
   * 민감 데이터 식별 및 태깅을 수행하고, 통합 액세스 제어를 통해 승인된 AE만이 검증 로직을 수정하도록 제한합니다.

## 4. '데이터 규약(Data Contract)' 기반의 협업 프로세스 및 DGR 프로토콜
데이터 규약은 DE와 AE 간의 **서비스 수준 협약(SLA)**이며, 협업 비용을 최소화하는 표준 프로토콜입니다.
**데이터 거버넌스 리뷰(DGR) 운영 가이드 (Mandatory)**
1. **DGR 프로토콜 수립:** DE와 AE가 정기적으로 소통하여 품질 이슈를 공유하고 규약을 동기화하는 **DGR 미팅을 의무화**하십시오.
2. **규약 현행화:** 발견된 품질 이슈 및 스키마 변동 사항을 즉시 데이터 규약에 반영하십시오.
3. **표준화된 저장소 운영:** YAML 기반의 데이터 규약 저장소를 공동 운영하여 소스 시스템 변경에 따른 파급 효과를 사전에 차단하십시오.
---
## 5. dbt 기반 4단계 메달리온 아키텍처 및 표준화 가이드
대규모 환경의 'Tangled logic(복잡하게 얽힌 로직)'을 방지하기 위해, 기존 3단계를 확장하여 로직을 엄격히 격리한 4단계 구조를 적용합니다.
### 5.1. 표준 레이어 및 명명 규칙 시스템
| 레이어        | 접두사     | 핵심 역할 및 적용 로직                                                                                       |
| ------------- | ---------- | ------------------------------------------------------------------------------------------------------------ |
| **Raw**       | `raw_`     | 소스 미러링(1:1 반영), 단순 타입 캐스팅 및 리네이밍 (비즈니스 로직 배제)                                   |
| **Staging**   | `stg_`     | **로직 격리 구역**, 유효하지 않은 데이터 필터링, 증분 모델(Incremental) 적용                               |
| **Catalog**   | `cat_`     | **Silver 핵심**, Mapping Table을 통한 이기종 소스 통합, **재사용 가능한 진실(Reusable Truth)**             |
| **Reporting** | `rpt_`     | 보고 목적 최적화, 요구사항 기반 집계 및 **의도적 비정규화(Denormalization)**                               |

### 5.2. 물리적 폴더 및 Intermediate 운영 규칙
* **Intermediate 모델 활용:** 각 레이어 내부에 `intermediate` 폴더를 운영하여 복잡한 변환 과정을 분리하십시오. 이때 명명 규칙은 **int_stg_**, **int_cat_**, **int_rpt_** 접두사를 엄격히 준수해야 합니다.
* **Private 모델 참조 제한:** `intermediate` 폴더 내 모델은 해당 레이어의 **'Private 모델'**로 간주합니다. **타 레이어에서 특정 레이어의 intermediate 모델을 직접 참조하는 행위는 엄격히 금지**됩니다. 이는 사이드 이펙트를 차단하기 위한 필수 규칙입니다.
* **물리적 관리:** 가독성과 성능을 위해 intermediate 모델은 가급적 ephemeral 또는 view로 설정하십시오.

# 결론 : 구조적 전환을 통한 데이터 운영 효율성 강화
Zerobus와 4단계 메달리온 아키텍처의 도입은 운영 복잡성을 제거하고, 데이터 신뢰성과 처리 속도를 동시에 확보하는 구조적 전환입니다. 이를 통해 엔지니어링 리소스는 고부가가치 영역에 집중되며, ELT 기반 검증 체계로 데이터 품질과 비용 효율성이 함께 강화됩니다.
### 기술적 단순화와 업무 효율성 극대화
1. **복잡성 세금(Complexity Tax) 제거:** 브로커 관리, 파티션 튜닝, 소비자 그룹 모니터링, 클러스터 업그레이드와 같은 고도의 전문 지식이 필요한 운영 부담이 사라집니다.
2. **엔지니어링 리소스의 재배치:** 데이터 엔지니어(DE)는 인프라 운영에 소모하던 시간의 **30~40%를 절감**하여 데이터 규약 설계와 같은 고부가가치 과업에 집중할 수 있게 됩니다.
3. **시스템 단순화:** 다중 홉 아키텍처를 단순화하여 데이터 수집에서 테이블 반영까지 **5초 이내**의 지연 시간을 달성, 비즈니스 대응 속도를 획기적으로 높입니다.
### 데이터 신뢰성 강화와 관리 비용 최적화
1. **사후 거버넌스 체계:** 원천 데이터를 빠르게 저장(Bronze)한 뒤, **Silver 레이어에서 집중적으로 품질을 검증하는 ELT 방식**으로 전환하여 데이터의 시맨틱 무결성을 확보합니다.
2. **저장 비용 최적화:** Delta Lake(Parquet)의 고압축 기술을 통해 **테라바이트(TB) 단위의 원시 데이터를 기가바이트(GB) 단위로 압축**하여 저장 비용을 대폭 절감합니다.
3. **거버넌스 가시성:** 수집된 모든 데이터의 계보(Lineage) 정보는 **1년간 보존**되어 과거 데이터의 흐름과 영향을 분석할 수 있게 합니다.
