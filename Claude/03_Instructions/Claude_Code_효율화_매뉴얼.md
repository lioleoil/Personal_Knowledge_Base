## 1. 왜 토큰이 많이 소비되는가?

이 저장소의 WorkLog 파일들은 매우 크다:
- `Python_Scripts_대화_학습_정리.md`: 3,264줄, 272개 대화
- `Gen1_Gen2_Labeling_대화_학습_정리.md`: 대규모
- `OpenLABEL_대화_학습_정리.md`: 45개 대화

**주요 낭비 패턴:**
1. 파일 전체를 읽을 때 (`Read` without `limit`) → 수천 줄을 context에 올림
2. 서브에이전트가 권한 없이 실패 → 메인 에이전트가 동일 작업 재실행
3. 콘텐츠를 verbatim 복사 → 중복 저장
4. 분석 없이 바로 파일 탐색 → 불필요한 반복 검색

## 2. 파일 읽기 전략

### 원칙: 항상 최소 범위 읽기

```
# BAD — 전체 읽기 (3000+ 줄)
Read(file_path="Python_Scripts_대화_학습_정리.md")

# GOOD — 필요한 구간만
Read(file_path="...", offset=715, limit=100)
```

### 대용량 파일 접근 순서

1. **Grep으로 위치 먼저 파악** → 라인 번호 확인
2. **Read with offset+limit** → 해당 구간만 읽기
3. **절대로 전체 파일을 반복해서 읽지 말 것**

```
# 1단계: Grep으로 라인 번호 확인
Grep(pattern="^### MySQL Provider", output_mode="content", -n=true)
# 결과: 715번 줄

# 2단계: 해당 구간만 읽기
Read(offset=715, limit=50)
```

### 파일별 예상 크기

| 파일 | 대략적 줄 수 | 권장 읽기 방식 |
|------|------------|--------------|

| Gen1_Gen2_Labeling_대화_학습_정리.md | ~2000줄 | Grep → 타겟 Read |
| OpenLABEL_대화_학습_정리.md | ~1500줄 | Grep → 타겟 Read |

## 3. 서브에이전트(Agent) 사용 전략

### 서브에이전트를 쓸 때

- 독립적인 병렬 작업 (Q1, Q2, Q3처럼)
- 결과만 필요하고 중간 과정은 불필요한 작업
- 탐색/리서치 목적 (Explore 에이전트)

### 서브에이전트 사용 시 필수 규칙

```markdown
## 서브에이전트 프롬프트에 반드시 포함할 것:

1. **파일 쓰기 권한이 필요함을 명시**
   - "Write/Edit 도구를 사용해야 하는 작업입니다"
   - 권한이 막히면 즉시 결과를 텍스트로 반환하도록 지시

2. **대용량 파일 읽기 전략 지정**
   - "Read 도구 사용 시 offset과 limit을 반드시 지정하세요"
   - "Grep으로 위치 확인 후 타겟 범위만 읽으세요"

3. **결과 형식 명시**
   - "파일 생성이 막히면 결과 마크다운을 텍스트로 반환"
   - "분석 결과만 필요, 원문 verbatim 복사 불필요"
```

### 서브에이전트 실패 시 처리

에이전트가 권한 문제로 실패하면:
1. 에이전트가 완료한 분석 결과를 반환값에서 추출
2. 메인 에이전트(나)가 직접 파일 작업 수행
3. 에이전트를 재시작하지 말 것 (토큰 낭비)

## 4. 작업 유형별 효율적인 접근법

### 4-1. 대화 재분류 작업 (Q1 유형)

**비효율적 방법:**
- 전체 파일 읽기 → verbatim 복사 → 새 파일에 붙여넣기

**효율적 방법:**
```
1. Grep으로 재분류 대상 헤딩 라인 번호 파악
2. 각 섹션별 핵심 내용만 요약 (날짜, 핵심, 메시지 수)
3. 대상 파일에 요약 형태로 append (원문 복사 금지)
4. 원본 파일에 "(→ 카테고리로 이동)" 표시만 추가
```

**토큰 절약 효과:** verbatim 복사 대비 약 80% 절감

### 4-2. 새 문서 생성 작업 (Q2, Q3 유형)

**비효율적 방법:**
- 모든 소스 파일을 순서대로 전체 읽기

**효율적 방법:**
```
1. 헤더 정보 (관련 대화 수, 기간)만 먼저 확인
2. 핵심 주제 목록 섹션만 읽기 (대화별 상세 내용 스킵)
3. 특정 날짜/주제가 필요하면 Grep으로 찾아서 타겟 Read
4. 이미 완성된 문서(역량맵 등)는 재생성하지 말고 참조만
```

### 4-3. 상태 확인 작업

```
# 에이전트 상태 확인 — 파일 전체가 아닌 JSON만
Read(.status/q1_status.json)  # 16줄, 최소 토큰
```

## 6. 에이전트 병렬 실행 모범 사례

### 병렬 실행이 유효한 경우

```
# 독립적인 파일을 각각 처리하는 경우 — 병렬 OK
Agent Q1: Python_Scripts 파일 분석
Agent Q2: 역량맵 생성 (다른 소스 파일들 참조)
Agent Q3: Career 파일 분석
```

### 순차 실행이 필요한 경우

```
# 의존관계가 있는 경우 — 반드시 순차
Step 1: WorkLog 파일들 읽기
Step 2: Step 1 결과 기반으로 새 문서 생성
Step 3: Step 2 완료 후 INDEX.md 갱신
```

### 에이전트 프롬프트 길이 최적화

- 배경 정보: 3~5줄 이내
- 작업 지시: 번호 목록으로 명확하게
- 불필요한 예시 코드 제거
- "중요 사항" 섹션은 핵심 2~3개만
