# Nova Platform — 2026 Q2 OKR 브레인스토밍 문서

> **작성 목적:** 2026 Q2 전략 방향 정렬 및 OKR 초안 수립을 위한 내부 브레인스토밍 자료
> **작성일:** 2025년 Q4 기준 | **버전:** v0.1 Draft

---

## 전략 맥락

| 전략 축 | 핵심 과제 | 비즈니스 임팩트 |
|---------|-----------|----------------|
| 🚀 **유저 유입 활성화 & Help Center** | 신규 유저의 초기 경험 개선, 셀프서비스 지원 체계 구축 | 온보딩 이탈률 감소 → 활성 유저 기반 확대 → 플랫폼 리텐션 지표 개선 |
| 🔗 **신규 도메인 통합 (ODD / Sensor)** | ODD(Operational Domain Data) 및 Sensor 데이터 파이프라인을 Nova Platform에 통합 | 데이터 커버리지 확장 → 고객사 유즈케이스 다양화 → 엔터프라이즈 계약 확대 |
| 🏗️ **아키텍처 전환 (Databricks 기반)** | 레거시 데이터 파이프라인 및 분석 레이어를 Databricks 기반으로 마이그레이션 | 처리 성능·안정성 향상 → 개발 속도 증가 → 기술 부채 감소 |

> **전략 간 상호작용:** 아키텍처 전환이 인프라 기반을 안정화하고, 도메인 통합이 플랫폼 가치를 확장하며, 유저 유입/Help Center가 그 가치를 사용자에게 연결하는 **3층 구조**로 동작합니다.

## OKR Set A — 유저 유입 활성화 & Help Center

> ### *"처음 쓰는 사람도 막히지 않는 플랫폼 — Discover, Activate, Stay"*

| 구분 | 내용 |
|------|------|
| **Objective** | Nova Platform의 신규 유저 온보딩 경험을 혁신하여, 첫 접속 후 핵심 가치를 30분 내 체험할 수 있는 환경을 만든다 |
| **KR 1** | 신규 가입 후 7일 이내 핵심 기능(대시보드 생성 or 첫 쿼리 실행) 완료율을 **현재 대비 +25%p** 향상 (예: 40% → 65%) |
| **KR 2** | Help Center 런칭 및 콘텐츠 충족: **FAQ 50건 + 워크스루 가이드 20건** 발행, 월말 기준 Help Center 통한 지원 티켓 대체율 **≥ 30%** 달성 |
| **KR 3** | 신규 유저 대상 NPS(Net Promoter Score) 온보딩 세션 점수 **≥ 40** 달성 (현재 측정값 기준 기저 설정 후 목표 설정) |

**전략적 근거:**
플랫폼 성장 초기 단계에서 유저 획득보다 **활성화(Activation)** 가 더 높은 ROI를 보이는 경향이 있습니다. 신규 유저가 첫 세션에서 "Aha-moment"를 경험하지 못하면 7일 리텐션이 급격히 하락합니다. Help Center는 CS 팀의 반복 부하를 줄이는 동시에, 유저가 스스로 문제를 해결하게 하여 플랫폼 신뢰도를 높입니다. KR1의 25%p 향상은 업계 평균 SaaS 온보딩 개선 사례(Appcues, 2024) 참고치이며, KR2의 30% 대체율은 Zendesk 벤치마크 기준 초기 목표값입니다.

## OKR Set B — 신규 도메인 통합 (ODD / Sensor)

> ### *"Nova가 다루는 세계를 넓힌다 — More Domains, More Value"*

| 구분 | 내용 |
|------|------|
| **Objective** | ODD 및 Sensor 도메인 데이터를 Nova Platform에 통합하여, 고객이 단일 플랫폼에서 다중 도메인 분석을 수행할 수 있도록 한다 |
| **KR 1** | ODD 데이터 파이프라인 연동 완료: **핵심 ODD 스키마 100% 매핑** + 파이프라인 안정성 SLA **≥ 99.5% uptime** (Q2 말 기준) |
| **KR 2** | Sensor 데이터 인제스천 및 조회 기능 베타 출시: 내부 파일럿 고객사 **≥ 3곳** 온보딩 완료, 평균 데이터 지연시간 **< 5분** (실시간 근접 처리) |
| **KR 3** | 통합 도메인(ODD + Sensor)을 활용한 크로스 도메인 분석 유즈케이스 **≥ 5건** 문서화 및 고객 데모 자료 완성, 이를 기반으로 엔터프라이즈 신규 파이프라인 상담 **≥ 2건** 창출 |

**전략적 근거:**
단일 도메인 플랫폼은 경쟁사 대비 교체 장벽이 낮습니다. ODD와 Sensor를 통합함으로써 Nova는 **데이터 허브**로 포지셔닝이 가능하며, 고객 이탈 비용(switching cost)이 비선형적으로 증가합니다. KR1의 99.5% SLA는 엔터프라이즈 계약 시 최소 요건이며, KR2의 5분 지연은 Sensor 기반 운영 모니터링 유즈케이스의 실용성 임계값입니다. KR3의 영업 파이프라인 창출은 Product-led Growth와 Sales 팀 간 연결고리를 만드는 데 의의가 있습니다.

## OKR Set C — 아키텍처 전환 (Databricks 기반)

> ### *"빠르고 믿을 수 있는 기반 위에 — Build the Engine, Scale the Platform"*

| 구분 | 내용 |
|------|------|
| **Objective** | 레거시 데이터 처리 아키텍처를 Databricks 기반으로 전환하여 플랫폼의 성능·확장성·개발 생산성을 근본적으로 향상시킨다 |
| **KR 1** | 레거시 파이프라인 중 **핵심 워크로드 Top 5 기준 80% 이상**을 Databricks로 마이그레이션 완료, 마이그레이션 후 평균 처리 시간 **≥ 30% 단축** |
| **KR 2** | Databricks 기반 파이프라인의 장애 감지 → 복구 MTTR(평균 복구 시간)을 **현재 대비 50% 감소** (예: 현재 60분 → 30분 이하) |
| **KR 3** | 신규 데이터 피처 개발 사이클(기획 → 배포) 리드타임을 **현재 대비 40% 단축**: Databricks Unity Catalog 및 Delta Live Tables 표준화 도입을 통한 개발 환경 통일화 완료 |

**전략적 근거:**
아키텍처 부채는 누적될수록 신규 기능 개발 비용을 기하급수적으로 증가시킵니다. Databricks 전환은 단순 기술 교체가 아니라, ODD/Sensor 통합(Set B)과 유저 경험 개선(Set A) 모두를 뒷받침하는 **플랫폼 기반 레이어**입니다. KR1의 30% 처리 시간 단축은 Databricks 공식 마이그레이션 케이스 스터디 평균치를 참고했으며, KR3의 40% 리드타임 단축은 Unity Catalog 도입 시 데이터 디스커버리·거버넌스 시간 절약 효과를 반영합니다.
